# 对话主题河流:聚类参数 K 与 τ

对话主题河流(topic_stream 的第三个 adapter,`source=conversation`)把 claude/codex/opencode 的对话聚成主题带,铺在时间轴上。它的"分成几条带、每条带算不算数"由两个聚类参数决定:**K**(聚类数)和 **τ**(far-drift 距离门槛)。

本文解释这两个参数是什么、怎么影响结果、真机基线数据,以及为什么调 K 不是想当然的杠杆。

- 代码:`src/topicStream/conversation.ts`(`CONVERSATION_K`、`CONVERSATION_TAU`、`kmeans()`、`nearestCentroid()`)
- 命名:`src/topicStream/conversationNaming.ts`
- 设计文档:gstack office-hours 产物 `~/.gstack/projects/<repo-slug>/*-topic-river-engine-design-*.md`

---

## 1. 这两个参数在管线里的位置

```
agent_user_messages (is_human=1, claude/codex/opencode)
  ↓  按 session 聚合 cleaned_text(滤注入噪声 + stripControlTags)
  ↓  rag embedder → 每会话向量(L2 归一,缓存)
  ↓  ┌─ 无码本 / --recluster：K-means(K) → 每簇 LLM 命名 → 冻结进 topic_codebook
  ↓  └─ 有码本:每会话向量 → 最近质心 → 距离 ≤ τ 取簇标签,距离 > τ 落「其他」
  ↓
topic_stream(source='conversation', category=带名, event_time=MIN(event_at_utc))
```

- **K** 只在**建/重建码本**(首次或 `--recluster`)时起作用:决定 K-means 把向量切成几组。
- **τ** 在**每次分配**时起作用:决定一个会话离最近质心多远就"不算这个主题"。

冻结码本的意义见 §6:码本一旦建好,普通 rebuild 只做"按最近质心分配",带的身份跨 rebuild 稳定,不会漂移。

---

## 2. K:聚类数(带的粒度)

`CONVERSATION_K = 12`(写死,有 `--k` 命令行覆盖)。

K-means 拿全部已 embed 的会话向量,按相似度切成 **K 组**,每组是一条候选带。之后同名簇合并(§5)、尾部落「其他」,所以**最终带数 ≤ K + 1**。

- **K 大** → 带更多更细。风险:把一个密集的主导主题切碎(见 §5 的「附件分析」)。
- **K 小** → 带更少更粗。风险:质心变少,更多会话离所有质心都远 → 掉进「其他」;小的真主题被并掉。

一句话:**K = 河流上有几条主题带(粒度)。**

### K 的距离度量

K-means 与最近质心都在 **L2 归一后的向量**上做,等价于 **cosine**(单位球面上欧氏距离与 cosine 一一对应)。种子固定(`CONVERSATION_KMEANS_SEED = 42`)+ k-means++ 初始化,所以同一批向量 + 同一 K → 同样的聚类,`--recluster` 可复现、单测可断言。

---

## 3. τ:far-drift 距离门槛(「其他」占比)

`CONVERSATION_TAU = 0.3`(写死)。

聚完之后,每个会话被分到**最近的质心**。τ 是一把尺子:若会话到最近质心的 **cosine 距离 > τ**,就不硬塞进那条带,直接落**「其他」**(`nearestCentroid()` 返回 `dist = 1 - dot`,`buildConversationEvents` 里 `dist > CONVERSATION_TAU ? 其他 : 簇标签`)。

cosine 距离:`0` = 方向完全一致,`1` = 完全正交(不相关)。所以 `τ=0.30` ≈「最像的主题都差了 30% 以上,就当它没主题」。

- **τ 小** = 严 → 只有很贴近的才留在带里,「其他」变大。
- **τ 大** = 松 → 几乎都被塞进最近的带,「其他」变小,但会开始把不相关的会话塞进错的带。

τ 的另一个作用是**吸收冻结后出现的新主题**:码本冻结后才冒出来的话题,离旧的 12 个质心都远,距离 > τ → 落「其他」,而不是被硬塞进某条不相关的旧带。没有 τ,「新主题涨起来」这个价值点就没了。

一句话:**τ = 对「勉强算这个主题」有多宽容,顺带决定「其他」有多大。**

---

## 4. 两者关系,一个比方

- **K** = 你设了几个带标签的文件夹。
- **τ** = 一份文件,离最近的文件夹差多远你还愿意塞进去、多远就丢进「杂项 / 其他」堆。

K 先决定桶的数量,τ 再决定"归桶"这件事有多苛刻。两者一起决定带的粒度和「其他」的大小。

---

## 5. 为什么调 K 不是干净的杠杆

真机上「附件分析」(图像/截图分析会话)是一个非常密集的大团(约占 37%)。实验发现:

- **K=12**:这个团被 K-means 切成 **4 个近似簇**,LLM 把它们命名成一样的名字。
- **K=8**(想让它并起来):**「其他」反而冲到 28%**(质心少了,小的真主题被饿死掉进其他),而「附件分析」**照样裂成 3 份**。

结论:**密集大团不靠全局 K 收敛**;降 K 只会牺牲多样的小主题、抬高「其他」。

真正的解法是 **同名簇合并**:LLM 把几个簇命名成同一个名字,这个"同名"本身就是合并信号。`conversationNaming.ts` 里**故意不给重复标签加后缀**,于是同名簇的 `category` 相同 → 在 `topic_stream` 里天然并成一条带。K 保持 12 让多样主题各自成带,冗余簇靠语义命名收拢。着色也按 `cluster_id` 定,同名带取同一颜色。

---

## 6. 冻结码本与稳定性

带能跨 rebuild 稳定读,是因为码本**冻结**:K-means 与 LLM 命名只在首次或 `--recluster` 时跑一次,质心 + 标签写进 `topic_codebook`(`rule_version='cluster-v1'`)。之后普通 rebuild 只做"按最近质心分配",同一会话落同一带、颜色不变。

想重排带(比如调了 K/τ、或想让码本吃进新会话)才用 `--recluster`,相当于 `git-repo-v1` 那种版本化码本的 bump。这也是为什么改 K/τ 后必须 `--recluster` 才生效:普通 rebuild 会加载旧码本、忽略新参数。

### τ=0.30 的来历(注意口径)

τ=0.30 最初是在**旧的 cosmos 向量**上探查定的(那批向量后来因被注入样板污染而被弃用,见设计文档的 pivot)。cosmos 向量上的 τ 分布:

| τ | 其他(cosmos 向量,已弃用口径)|
|---|---|
| 0.25 | 23.9% |
| 0.30 | 10.1% |
| 0.35 | 3.7% |

pivot 到**清洗后用户消息的新 embedding** 后,只验证了 `τ=0.30 → 其他 20.6%`(以及 `K=8 → 其他 28%`)。**新语料上的完整 τ 分布尚未重扫**——这是设计里明确留的待办:换 embedding 语料后 τ/K 都应在新语料上重探再定死。当前 20.6% 是可接受区间,故沿用 0.30。

## 8. 现状与调优

- 现状:`CONVERSATION_K` / `CONVERSATION_TAU` 写死在 `conversation.ts`。`--k` 命令行可覆盖 K;τ 无命令行开关。
- 调 K/τ 后必须 `topics rebuild --source conversation --recluster` 才生效。
- **config 化(待做)**:把 K/τ(以及冷启动线)挪进 `~/.ai2nao/config.json`,像 chrome taxonomy 那样不改代码可调。这是"想让带多一点 / 其他少一点时自己拧"的正规入口。

### 调优直觉

- 觉得**带太碎 / 同一主题裂成好几条** → 先看是不是密集大团(如附件分析),那是同名合并的活,不是降 K(见 §5)。
- 觉得**「其他」太大**(如 > 30%)→ 调**大 τ**(如 0.35)让更多会话归带;或看是不是 K 太小导致质心不够。
- 觉得**「其他」太小 / 不相关的会话被塞进带** → 调**小 τ**(如 0.25)收紧。
- 觉得**真主题被并掉、想更细** → 调**大 K**,但盯住「其他」别涨、盯住密集团别裂。

每次调完在真机重跑 `--recluster`,看带表和「其他」占比,再决定下一步(照 chrome taxonomy 从 76%→25.6% 那次"先看分布再拧"的路子)。
