# ADR-0002：Kimi 会话列表的主干改成「token 索引 ∪ 只有正文的会话」

Kimi 列表原来是 `FROM kimi_agent_token_usage LEFT JOIN agent_user_messages` —— token 索引决定有哪些会话，正文表只贴计数和首句。这个耦合是因为**会话级元数据只有 token 索引里有**：标题、模型、agent 数、项目绝对路径都来自 `state.json`，而只有 `kimi.tokens.refresh` 会去读它；正文入库那条路径压根不碰 `state.json`，而且正文表的 `project` 是 slug，本仓库禁止做 slug→路径的有损反解。

代价在一台真机上暴露出来：`kimi.tokens.refresh` 是关着的（本仓库所有定时任务都以关闭状态入库，要用户自己开），而正文同步开着、每小时在跑。结果 49 场会话里有 17 场只有正文，**在这个页面上静默不存在**，目录旁边的会话数也偏小，界面上没有任何提示。

现在主干改成两者的并集：token 索引里还在的，加上索引**压根没见过**但已经有正文的。后者列出来但标记 `tokenIndexed: false`，界面收进一个「待索引」桶，诊断条直接点名是哪个定时任务关着。

## 为什么不是简单地以正文表为准

正文表**不会**因为 wire.jsonl 被删而减行，而 token 索引会给消失的文件标 `missing_since`（不删行）。以正文为准会把已经消失的会话请回列表。所以并集的第二项要减掉「索引见过但已标记消失」的会话 —— 判据是「在 `kimi_agent_token_usage` 里一行都没有」，而不是「不在存活集合里」：后者会误伤那种一个 agent 消失、另一个还在的会话。

## 为什么「待索引」不能并进「(未知项目)」

`CONTEXT.md` 把「未知项目」定义成**确定不属于任何工作目录**（桌面沙箱里的随手提问），而「待索引」是**还没查出来**。两者在界面上的含义、在数据上的成因、以及该不该报诊断都不同。并成一个桶会让一个索引缺陷长得像一条正常记录。

## 后果

- 左栏多一个桶，沉在最底（顺序：真实目录 → (未知项目) → 待索引）。
- 待索引的会话没有标题（显示「无标题会话」）、没有模型、agent 数为 0，时间退回正文的首尾事件时间。
- `KimiDashboardSessionRow` 多一个 `tokenIndexed` 字段，前端据它分桶。缺这个字段的旧夹具会让所有会话看起来是待索引 —— 这是故意不给默认值：静默兜底会把真正的后端缺陷藏起来。
