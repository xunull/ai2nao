# AI Chat Web Search

Generated by `/plan-ceo-review` on 2026-05-17.

Repo: `xunull/ai2nao`

## Goal

AI Chat should gain web search as a backend capability, not as a CopilotKit frontend tool dependency.

CopilotKit remains the chat UI shell. ai2nao owns the tool system, provider abstraction, security boundary, evidence model, and persistence.

The differentiated product shape is not generic web search. It is local RAG evidence plus current web evidence in one inspectable answer surface.

## Architecture

```text
AI Chat UI (CopilotKit shell)
  -> forwardedProps: webSearchEnabled
  -> /api/copilotkit
      -> ai2NaoSystemPrompt
      -> buildAi2NaoServerTools()
          -> ai2nao_web_search
              -> sanitizeWebSearchQuery
              -> WebSearchCache
              -> SearchProvider
                  -> BraveSearchProvider
              -> WebSearchEvidence
      -> streamText({ tools })
      -> AG-UI messages/tool results
      -> SQLite raw_json persistence
  -> reload session
  -> final answer cites LOCAL + WEB evidence titles and URLs/paths
```

## Data Flow

```text
User asks current/external question
  -> model decides search is needed
  -> ai2nao_web_search({ query, reason })
  -> webSearchEnabled? else ToolUnavailableError
  -> sanitize query
      -> sensitive? SensitiveQueryBlocked
  -> cache lookup by provider + queryHash
      -> hit? return cached results
      -> miss? Brave provider request
  -> normalize results
  -> emit tool result
  -> persist raw AG-UI message
  -> synthesize final answer with evidence citations
```

## Error Registry

| Codepath | Failure | Error | User impact |
|----------|---------|-------|-------------|
| `readWebSearchConfig` | Missing key | `config_missing` | Web Search disabled, chat/RAG still works. |
| `BraveSearchProvider.search` | Invalid key | `SearchProviderAuthError` | Setup hint in status/diagnostics. |
| `BraveSearchProvider.search` | Rate limited | `SearchProviderRateLimitError` | Search unavailable until provider recovers. |
| `BraveSearchProvider.search` | Timeout | `SearchProviderTimeoutError` | Tool result says search timed out. |
| `BraveSearchProvider.search` | Malformed JSON | `SearchProviderParseError` | Tool result says provider response invalid. |
| `sanitizeWebSearchQuery` | Sensitive text detected | `SensitiveQueryBlocked` | User sees rewrite/confirmation guidance. |
| `webSearchTool.execute` | Toggle off | `ToolUnavailableError` | No outbound request is made. |
| `streamText` tool execution | Malformed args | `ToolInputValidationError` | Tool result explains invalid query/count. |
| Session persistence | Tool/result message shape | `LlmChatSessionError` | Must be covered by tests before shipping. |

## Security

- Brave key stays server-side only.
- Browser code never receives provider credentials.
- Logs use a whitelist: provider, configured status, error class, duration, result count, and `queryHash`.
- Logs must not include Authorization headers, raw provider responses, full sensitive queries, or API keys.
- Web Search OFF is enforced by tool construction and execute-time checks.
- Sensitive query blocking is lightweight, not a full DLP engine.

## Engineering Review Addendum

Generated by `/plan-eng-review` on 2026-05-17.

### Locked Decisions

- Implement the v1 runtime scope in dependency order: persistence protocol, `src/webSearch`, server-side tools, final-answer evidence synthesis, then full verification.
- Remove frontend CopilotKit business tools from `/ai-chat`; CopilotKit remains the UI shell.
- Reject any client-provided CopilotKit tools at `/api/copilotkit`; all AI-callable tools are built server-side.
- Set AI SDK `streamText` `maxSteps: 3` so tool-call results can be followed by a final assistant answer.
- Route and tool entrypoints must both call one shared `webSearchService.search()`.
- Migrate RAG evidence to the same backend tool/result path as Web evidence; automatic RAG prompt injection should be disabled or treated only as a compatibility fallback.
- RAG and Web tools must return one stable `AiEvidenceToolResult` envelope.
- Sensitive query blocking returns a recoverable `evidence_error` with rewrite guidance; the backend must not auto-rewrite and re-search.
- `webSearchService` uses dependency injection for config, provider, cache, diagnostics, clock, and fetch.
- AG-UI tool/result messages are persisted as raw JSON, but title, preview, and message count derivation must be role-aware.
- `queryHash` uses a process-random salt with HMAC/SHA-256 and is not stable across restarts.
- Evidence field truncation happens before JSON serialization; the final envelope must always be valid JSON.
- Cache keys use conservative normalization: trim, collapse whitespace, lowercase; no punctuation removal or tokenization.
- RAG and Web evidence use per-source budgets before the final envelope budget.

### Test Requirements

- Add deterministic fake model/runtime tests for tool-call -> tool-result -> final-answer -> persistence.
- Add release smoke eval cases for Web tool trigger, RAG tool trigger, no-tool prompt, and sensitive-query blocking.
- Keep real local-model curl/SSE smoke as manual release verification, not as required unit CI.
- Session tests must cover both legacy text-only messages and new assistant toolCalls / `role: tool` messages.

### Implementation Order

```text
3. server-side RAG/Web tools + client-tools rejection

```
